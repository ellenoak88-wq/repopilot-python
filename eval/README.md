# LoopForge 源码召回黄金集

本数据集覆盖 `Tencent/LoopForge` 的真实导入快照，固定 Git 提交和 RepoPilot 的文件集合指纹见 `loopforge.snapshot.json`。第 2 版共 42 个中文问题，均来自仓库源码和文档，不含个人聊天记录。标注由 Codex 对照快照核验，尚未经过项目维护者独立复核。

## 题目与证据

`loopforge.jsonl` 每行一题。开发集 28 题（26 道可回答），保留测试集 14 题（13 道可回答）。同一主题的近似题放在同一个划分。题目涵盖安装、编译、配置、Runner、定时调度、遥测、计费和异常处理。3 道现场问题单列，`missing_evidence` 说明需要补充的信息。

第 2 版保留前版 30 个问题，重新核对全部出处。LF-003 的 shell 分支、Compose 服务以及 LF-014 的工作区锁函数各自缩小到能独立证明事实的行。新增 12 题覆盖工作流任务与矩阵、函数、测试用例、构建阶段、包命令入口、文档小节及跨文件查证。全套共 62 个必需事实、69 处可接受的源码出处。开发与保留划分沿用既有题号，新题按主题归组。证据以真实文件和行号标注，不依赖任何检索器产生的块 ID。

每个 `evidence_groups` 条目对应一个必须证明的事实。组内 `any_of` 的任一片段即可证明它；组间全部命中才算完整。文件行号从 1 起、两端均包含；SHA-256 校验该范围的 UTF-8 原文（行间使用 LF，不附加末尾换行）。标注是已审核出处的集合，发现等价依据时可复核并加入。仓库更新后应在新版本重新核对范围。

## 使用

打开 RepoPilot 的 LoopForge 项目，在「混合检索设置 → 检索评测」选择题集，点击「运行对照评测」。完成后点击「下载最近报告」。同一次运行的 BM25 和混合检索指标写入一份 JSON，默认宿主路径为 `data/evaluations/loopforge-dev-compare.json`，保留集文件名使用 `test`。每个划分只在新一轮成功时替换最近报告；修改 Compose 数据目录后，报告跟随该目录。

在 RepoPilot 项目根目录用 PowerShell 7 运行：

```powershell
.\.venv\Scripts\python.exe -m eval.run_loopforge
.\.venv\Scripts\python.exe -m eval.run_loopforge --mode compare
.\.venv\Scripts\python.exe -m eval.run_loopforge --mode bm25 --output bm25-dev.json
.\.venv\Scripts\python.exe -m eval.run_loopforge --mode hybrid --output hybrid-dev.json
```

也可以在已部署的容器内执行 `docker compose exec app python -m eval.run_loopforge` 校验，或加 `--mode hybrid` 评分。

默认从 `data/repopilot.db` 只读验证全部标注。使用其他数据目录时传 `--db`；模型缓存支持 `EMBEDDING_CACHE_DIR`。评分在数据库的一致性临时副本上进行。混合检索需先建好相同快照的真实向量索引；出现降级时命令会提示原因并停止评分。开发集报告含逐题前五十条路径和行号、各证据组首次出现的排名、平均证据召回率、完整命中率和 MRR@5。现场问题不计入召回分母，可单独评估 Agent 能否指出证据不足。

日常调参使用默认的 `dev`。锁定方案后再传 `--split test` 复测保留集。开发集报告包含逐题排名；保留集报告仅含汇总指标与题数。评测只复制目标仓库源码和当前向量索引，每题只把问题文本传给检索器，查询之间不携带会话、Wiki、学习档案或标准证据。当前任务衡量首轮源码召回。

## Top‑5 与 Top‑50

报告第 3 版对每道可回答的问题、每种检索方式请求一次 50 条结果。Top‑5 取这一榜单的前五条，Top‑50 取前五十条，实际返回较少时使用全部已返回片段。

- **问题命中率**（`hit_rate_at_5`、`hit_rate_at_50`）以可回答问题为分母。只要前 K 条合起来覆盖至少一个完整的必需证据组，该题就命中。
- **证据覆盖率**同时报告 `union_recall_at_5`、`union_recall_at_50` 和对应的 `single_chunk_recall_at_5`、`single_chunk_recall_at_50`。这些指标按题平均，能区分只找回一条证据和找全多个事实。
- **逐题溯源**使用 `results_at_50` 查看前五十条的路径和行号，`union_ranks_at_50` 和 `ranks_at_50` 给出各证据组首次联合覆盖、单片段覆盖的排名。名次为 6–50 表示扩大阅读范围后才命中。旧字段仍只描述前五条。保留集报告只提供汇总。

混合检索的候选池随请求数量扩展。请求 50 条时从最多 150 个融合候选中重排，请求 5 条时从最多 30 个候选中重排。因此本版 Top‑5 可能与历史基线或聊天实际请求 5 条时的结果不同。比较阅读深度时应使用同一份报告里的两个截点。

## 报告中的两种证据覆盖率

| 用途 | JSON 指标 | 每个证据组的命中条件 |
| --- | --- | --- |
| 主要指标：Agent 在前五条中能读全多少证据 | `union_recall_at_5` | 同一出处的全部源码行都被前五个片段覆盖，可以拼接同文件中相邻或重叠的片段。 |
| 辅助指标：切片是否保留了完整证据 | `single_chunk_recall_at_5` | 前五条中至少有一个片段独自覆盖一处完整出处。 |

例如，证据在同一文件第 10–18 行，召回的两个片段分别覆盖第 10–13 行和第 14–21 行，主要指标命中，辅助指标未命中。如果后一个片段从第 15 行开始，两项都未命中。每组的等价出处独立核对，任一出处完整覆盖即可得一分。

两个比例都先按题计算「命中组数 / 必需组数」，再对可回答的问题等权平均。另见 `evidenceCounts` 的原始组数（`union`、`single_chunk`、`total`）。开发集的 `union_ranks` 记录每组证据最早在前几条合起来时读全，`ranks` 是首次单片段命中的名次。历史字段 `recall`、`complete`、`reciprocal_rank` 沿用单片段口径。`evidenceCountsAt50` 给出前五十条的原始证据组数。第 2 版历史报告仅记录 Top‑5。

## 降低背题风险

同一事实的改写题及共享核心证据的题应放在同一个划分。开发期间只查看开发集失败样本；锁定版本后再测保留集。随仓库提交的保留题可被拥有仓库访问权的人或编码助手读取，隐去逐题分数只能减少调参反馈。正式验收宜另备未公开的新题和新仓库版本，交由独立评测方维护，并限制读取权限。

评测服务支持 `REPOPILOT_EVAL_DIR` 指向仓库之外的评测目录，其中放同名的 `loopforge.snapshot.json` 和 `loopforge.jsonl`，格式与本目录一致。Docker 可将独立题库只读挂载，再把该变量设置为容器内路径。题库和评分报告不要加入项目索引、Wiki 或微调语料。每份报告记录题集哈希，便于区分换题与算法变化。使用拥有宿主机文件读取权限的编码助手时，应在独立账户或评测机保管真正的盲测集。

新版使用相同题集、源码、模型、Top-5 和评分逻辑对比旧窗口和结构化切片。报告中的 `snapshot.target_chunker` 记录题集设计时对应的切片规则，`chunkerVersion` 记录本次实际使用的版本。旧版结果应以旧代码和对应向量索引运行。第 1 版题集和基线保存在 Git 提交 `d78432b`。

## 第 2 版开发集结果

同一 LoopForge 快照的 2,828 个文件，旧规则产生 9,413 个窗口，新规则产生 30,469 个可引用片段。两个版本各自使用对应的真向量索引。26 道可回答的开发题参与评分，另 2 道现场题排除。

| 切片规则 | 检索方式 | 主要 · 五片段联合覆盖率 | 辅助 · 单片段覆盖率 | 联合 / 单片段命中组数（共 42 组） |
| --- | --- | ---: | ---: | ---: |
| 固定行窗口 | BM25 | 7.69% | 7.69% | 2 / 2 |
| 结构化 | BM25 | 11.54% | 11.54% | 3 / 3 |
| 固定行窗口 | 混合检索 | 17.31% | 17.31% | 7 / 7 |
| 结构化 | 混合检索 | 21.15% | 21.15% | 8 / 8 |

结构化切片按已保存的 Top‑5 路径及行号复算。固定窗口历史基线只保存了单片段排名。按当时的 65 行窗口、53 行步长逐条检查开发集出处后，所有未单独包含某一出处的窗口，即使全部合并，也覆盖不全该出处，因此这份历史基线的两项命中数相等。

例如，外接 MySQL 的配置说明（LF-006）进入混合检索第 4 名，E2E 的 Python 3.8 runner 选择理由（LF-038）从第 2 名升至第 1 名。新版混合检索仍有 21 道题未找全必需证据。完整对照保存在 `loopforge.dev-baseline.json`，各题按事实记录首次命中名次，`null` 表示前五条未覆盖。有多处等价出处的事实只计一次。14 道保留题只校验了标注和源码哈希。
