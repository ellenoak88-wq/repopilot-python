# 第三轮扩展：项目上手清单

打开仓库后，展开页面上方的「项目上手清单」，点击「生成上手清单」。

## 任务与依据

清单按「了解项目、安装与启动、阅读代码、验证与测试、第一次贡献」组织任务。生成器从当前索引的 README、文档章节、依赖配置、入口候选文件、测试样例和贡献指南中选择依据，不调用模型。

每项任务附有文件路径、行号和原文摘录。点击来源按钮可打开源码阅读器。入口候选根据文件名识别，不等同于已确认的应用入口；安装与测试步骤仍需要阅读原文后自行操作。没有足够依据的环节标记为「待确认」，不会补造命令或文件路径。

## 进度与备注

- 勾选任务记录完成状态，进度条随之更新。勾选仅代表手动记录，不代表系统运行或验证了命令。
- 展开「添加备注」，输入最多 1000 字并点击「保存备注」。未保存备注期间暂停导出，以免导出内容与已保存状态不一致。
- 清单按仓库保存到 SQLite，切换聊天会话、刷新页面或重启 Docker 都不会丢失已保存进度。
- 「导出清单」生成 Markdown，包含任务完成状态、备注、来源原文和 commit 信息。
- 多页面同时修改时使用版本检查，较旧页面的更新会被拒绝并刷新，避免静默覆盖。

## 重新生成与索引变化

同一索引重新生成会保留依据未变化任务的进度和备注。仓库 commit 或已索引文件集合、内容发生变化时，旧清单保留并显示过期提示；暂停进度编辑和源码跳转，避免旧行号指向新内容。

这时点击「重新生成清单」需要确认重置旧进度和备注。确认后，清单使用当前索引重新建立。旧清单在重新生成前仍可导出。

## API 与存储

- `GET /api/checklist?repo=owner/repo`：读取清单、阶段列表与过期状态。
- `POST /api/checklist/generate`：生成清单；传 `repo`、`planId`、`revision`。首次生成使用 `planId: null`、`revision: 0`。
- `POST /api/checklist/update`：更新任务；传 `repo`、`planId`、`revision`、`taskId` 以及 `completed` 或 `note`。

成功操作返回完整清单与新的版本信息；过期写入和并发版本冲突返回 409。新建的 `checklists` 表自动创建，不修改原仓库文件或聊天历史。无需新依赖或额外环境变量。

## 验证

新增 11 项测试，覆盖来源行号、缺失依据、稳定任务 ID、备注和进度持久化、同索引重新生成、版本冲突、重新索引过期、输入校验及仓库隔离。自动测试合计 49 项通过。

浏览器验收覆盖勾选、保存备注、源码跳转、Markdown 导出、刷新恢复、并发冲突、过期禁用、仓库隔离和 390px 手机布局；容器重启后已保存进度与备注仍然存在。
