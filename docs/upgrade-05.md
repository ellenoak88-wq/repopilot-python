# 第五轮扩展：BM25 + 本地向量混合检索

打开已导入仓库，在「混合检索设置」点击「建立向量索引」。完成后，问答默认使用混合检索；右侧「代码搜索」也可选择「混合检索 · BM25 + 向量」。已有会话、源码引用和上手清单不受建立向量索引影响。

## 检索过程

1. BM25 在当前仓库的片段上搜索关键词，保留原有中文查询扩展。
2. 本地多语言模型把问题转成向量，与已保存的片段向量计算余弦相似度。长片段按模型分词器的溢出窗口分别向量化，取各窗口与问题的最大相似度作为片段分数。
3. 两路候选使用 Reciprocal Rank Fusion（RRF，`k=60`）合并：每条排名贡献 `1 / (60 + rank)`。不直接相加量纲不同的 BM25 分数与余弦相似度。相同文件、起止行的结果合并并显示召回渠道。
4. 返回的文本和行号仍来自当前源码索引；Agent 首次检索及 `search_code` 工具都使用相同的检索方式。向量结果是相似性候选，不代表已证明与问题相关，回答仍需核对源码依据。

问答设置可以切回「关键词检索 · BM25」；代码搜索的精确关键词和 BM25 相关片段模式继续可用。混合代码搜索的候选池最多 150 个片段，显示的数量是候选池去除重叠后的数量，不是全仓库匹配总数。路径筛选应用于两路召回。

## 本地模型与运行环境

使用 FastEmbed 0.9.1、ONNX Runtime CPU 和 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`，支持中文问题与英文文档间的语义匹配。它是通用多语言文本模型，不是代码专用模型；保留 BM25 有助于函数名、路径和标识符检索。

权重固定到 Hugging Face 仓库版本 `faf4aa4225822f3bc6376869cb1164e8e3feedd0`。完整缓存优先离线加载；普通查询不下载缺失权重，而是明确回退 BM25，下载由建立索引操作触发。

首次建立索引下载约 220 MB 的量化权重，另有分词和配置文件；耗时取决于网络。无需额外 API Key，不调用聊天模型生成 embedding，不把源码或问题发到第三方向量 API。聊天生成仍沿用原来的模型配置。

- 本地默认缓存：`data/models`；可用 `EMBEDDING_CACHE_DIR` 修改。
- Docker 固定缓存：`/app/data/models`，随现有 `./data` 卷持久化；权重不放进镜像或 Git。
- 依赖已锁定到 `uv.lock` 和带哈希的 requirements 文件。CPU 推理在工作线程执行，不阻塞健康检查；同一进程的模型推理串行执行，限制 CPU 线程数为 2。
- 每个仓库最多 10,000 个向量窗口。超限或失败时不保存半成品，不会改变原源码索引。

模型与库参考：[FastEmbed 支持的模型](https://qdrant.github.io/fastembed/examples/Supported_Models/)、[FastEmbed 本地推理说明](https://qdrant.tech/documentation/embeddings/fastembed/)。

## 持久化、过期与回退

SQLite 新增 `vector_indexes` 表，存储仓库、内容指纹、模型标识、片段数、窗口数、建立时间和向量数据。指纹包含 commit、文件路径、行号、文本及向量处理版本。新内容、新 commit 或模型版本变化时旧向量不再参与检索，页面显示过期并提供重建。

向量索引缺失、过期，或查询向量计算失败时，自动使用 BM25，并在代码搜索状态和问答执行步骤中明确说明。不会把 BM25 回退结果标成混合结果。「重建向量索引」可重新生成；整个新索引成功后才替换旧索引。

索引建立属于后台任务，页面显示进度。建立期间暂不允许导入或聊天生成；已有文件仍可阅读。关闭页面不会删除已保存数据。应用关闭导致任务取消时，不提交不完整索引。首次模型下载不在自动测试中执行，避免 CI 依赖外部权重服务。

## API

| 接口 | 用途 |
| --- | --- |
| `GET /api/retrieval/status?repo=owner/repo` | 查询 `missing`、`stale` 或 `ready` 及模型、片段、窗口和时间 |
| `POST /api/retrieval/build` | JSON：`repo`，可选布尔值 `force`；返回 202 和任务 ID |
| `GET /api/jobs/{id}` | 轮询建立进度；完成时返回 `index` |
| `GET /api/search?repo=owner/repo&q=问题&mode=hybrid` | 混合代码搜索；可传 `path` 和 `limit`；返回召回渠道与实际检索模式 |
| `POST /api/chat`、`POST /api/chat/stream` | 增加 `retrieval: hybrid`（默认）或 `bm25`；与 `mode: agent/extractive` 独立 |

「检索摘录」只表示不调用生成模型；选择混合检索且索引就绪时仍会运行本地 embedding 模型。

自动测试涵盖 RRF 排名与去重、语义补充召回、BM25 显式选择、向量数值校验、持久化、仓库隔离、内容与模型变更过期、路径过滤、故障回退、取消不写入半成品、并发建立、索引期间内容变化、API 输入校验，以及 Agent 首轮和工具搜索统一接入。

本轮共 73 项自动测试通过。真实模型验收确认中文问题可以召回英文说明，长片段生成多个窗口；在 `HF_HUB_OFFLINE=1` 的隔离实例中验证建立索引、混合搜索、问答引用、BM25 切换、源码阅读器、页面刷新恢复及 390px 手机布局。浏览器无脚本错误；验收会话保存在独立测试数据库，未写入原有用户会话。
